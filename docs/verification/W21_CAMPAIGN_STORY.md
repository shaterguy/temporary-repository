# W21 campaign story, recovery and ending contract

Task: `SR-20260909-150106-PPO12Y`
Target branch: `v1.0.0-dev1`
World schema: `lanternfall-world-v2`
Save payload envelope: `lanternfall-save-payload-v1`

## Scope

W21 extends the already-verified five-parent-region topology without changing package identity, signing lineage, versionName/versionCode, the outer save envelope, or settlement-ID semantics. The authored campaign layer adds 40 choice events, persistent event outcomes, failure-recovery scenes, actual next-expedition consequences, recurring character arcs, and persistent multiple endings. W22 long-term variant expeditions/mastery/challenges are intentionally not started here.

## Authored event contract

- `game/data/campaign_story_event_catalog.gd` owns exactly 40 authored events and 80 visible options.
- Each of the five parent regions owns eight events: four `success` follow-ups and four `failed` recovery events.
- Event IDs, titles, speaker IDs, arc IDs and bodies are explicit authored data. The catalog is not generated by recoloring or numeric cloning.
- Eleven recurring character arcs connect regional events: Mira, Dojin, Sori, Nara, Yeonhwa, Sion, Hae, Bora, Gyeom, Yeon and Tari.
- Each event option writes a unique story flag and selects one disclosed mechanical profile. Profiles alter a bounded combination of salvage/tension/world-axis state plus the next expedition's support, shop modifier, threat route and recovery assist.
- Event selection does not remove access rights or horizontal unlocks. Failure events cannot create a permanent dead end.
- A region/outcome pool does not repeat an event until its four authored events have been exhausted; later post-final cycles may reuse that pool deterministically.

## Runtime and save contract

1. Expedition settlement remains idempotent under the existing `settlement:<expedition_id>` ledger.
2. A successful or failed settlement schedules one regional story event when no older event is pending.
3. The main hub intercepts the normal `1`/`2` world-choice input while a story event is pending and resolves one of the two story options transactionally through `CampaignRuntime.resolve_story_event`.
4. A resolved option persists its event history, story flag, horizontal event-path unlock and one-run `next_expedition_modifier`.
5. The next actual expedition consumes that modifier into `active_expedition_modifier`; `expedition_context()` then exposes the modified `support_id`, `shop_modifier`, `threat_route`, `recovery_assist` and `story_modifier_id`.
6. Save failure leaves the live world unchanged because story resolution is first applied to a candidate world and only committed after `SaveStore` succeeds.
7. Pending and resolved event state, next/active modifiers, event histories and endings are optional fields inside `lanternfall-world-v2`. This keeps turn-29 v2 saves readable and leaves the outer `lanternfall-save-payload-v1` unchanged.
8. Legacy/pre-narrative campaign-complete v2 saves receive a deterministic compatibility ending only when no unresolved final story event exists.

## Ending contract

The first successful final-branch event choice finalizes one of four persistent ending identities:

- `harbor_of_many`
- `road_beyond_eclipse`
- `constellation_compact`
- `archive_of_dawn`

The ending is an epilogue/world-state result, not a hard stop. The two post-final departures remain available after resolution, so campaign completion does not create a dead end. W22 will build long-term variant expeditions and mastery on top of this retained continuation surface.

## Automated acceptance

`tests/unit/test_w21_campaign_story.gd` verifies:

- exact 40/80 catalog counts and 8-per-region, 20-success/20-failure distribution;
- unique event/option identities and authored narrative metadata;
- four-event no-repeat selection per region/outcome pool;
- success-event consequence reaching the next expedition context;
- failed-expedition recovery event preserving the same campaign segment and two progress paths;
- pending/resolved save-restore and no duplicate event application;
- final choices producing at least two distinct ending identities while preserving post-final paths.

`tests/integration/w21_campaign_story_smoke.gd` verifies through the actual `main_shell.tscn` and `CampaignRuntime` that a final regional settlement persists a pending event, reloads it, routes hub input to the event rather than an expedition, persists the ending, reloads the ending and then applies the event modifier to the next real post-final expedition.

The existing `tests/integration/w21_campaign_topology_smoke.gd` remains a non-regression gate for topology, migration, branch identity and checkpoint/reload.
